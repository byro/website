# byro.info

Source of the public project website for [byro](https://github.com/byro/byro),
served at <https://byro.info> via GitHub Pages. The site introduces byro in
German and English and links to the documentation on Read the Docs, to GitHub
and, once it exists, to the demo installation. The documentation itself stays
in the byro repository and on Read the Docs.

The site is plain HTML and CSS, generated by a small Python script
(`build.py`) from Jinja2 templates. There is no JavaScript framework and no
Node.js toolchain; the only dependency is Jinja2.

## Layout

| Path | Contents |
|---|---|
| `config.toml` | Central settings: site URL, languages, GitHub and documentation links, demo link and login |
| `content/de.toml`, `content/en.toml` | All texts per language, with identical keys |
| `templates/` | Jinja2 templates: `base.html`, the pages, `partials/`, and the inline icons in `icons/` |
| `static/` | CSS, font, logo, preview images and screenshots; copied to `/assets/` |
| `build.py` | Renders all pages, `sitemap.xml` and `robots.txt` into `build/` |
| `check.py` | Checks a build: internal links and assets, `lang`, titles, descriptions, canonical and hreflang links, sitemap, robots.txt, no resources from other hosts |
| `tests/` | Tests for `build.py` and `check.py` |
| `.github/workflows/pages.yml` | Checks pull requests, deploys `main` to GitHub Pages |

Generated pages:

| URL | Page |
|---|---|
| `/` | Neutral start page in German with links to both languages (see [Languages](#languages)) |
| `/de/`, `/en/` | Home page per language |
| `/de/demo/`, `/en/demo/` | Demo login details; only built while `demo.url` is set |
| `/404.html` | Bilingual "page not found", served by GitHub Pages for unknown URLs |

## Local development

Requires Python 3.13 (see `.python-version`; newer versions work as well).

```console
$ python3 -m venv .venv
$ .venv/bin/pip install --require-hashes -r requirements.txt
$ .venv/bin/python build.py            # writes build/
$ .venv/bin/python check.py            # checks build/
$ .venv/bin/python -m unittest discover tests
$ python3 -m http.server -d build 8000 # http://localhost:8000/
```

There is no file watcher: after changing a file, run `build.py` again and
reload the page. The local server does not serve `404.html` for unknown URLs;
GitHub Pages does.

To build for another URL, for example a GitHub Pages project URL, set
`SITE_URL`. Canonical URLs, hreflang links, the sitemap and all internal links
then use that URL and its path:

```console
$ SITE_URL=https://byro.github.io/website .venv/bin/python build.py /tmp/site/website
$ SITE_URL=https://byro.github.io/website .venv/bin/python check.py /tmp/site/website
$ python3 -m http.server -d /tmp/site 8000  # http://localhost:8000/website/
```

`requirements.txt` pins Jinja2 and MarkupSafe with hashes. To update them,
change `requirements.in` if needed and regenerate the file with the command in
its header.

## Changing content

- **Texts:** edit `content/de.toml` and `content/en.toml`. Keep the keys of both
  files in sync; a missing key fails the build. Only describe what the byro
  repository or its documentation backs up.
- **Links and settings:** edit `config.toml`. The documentation links are
  built from `links.docs.<language>` plus a page path, which is the same in
  both documentation trees (for example `installation/overview/`).
- **Layout:** templates are in `templates/`, styles in `static/css/site.css`.
  Colors follow the byro documentation (Zensical theme, primary color
  "indigo"), the font is Inter as in the documentation, but served from this
  site instead of Google Fonts.
- **Feature cards and showcase sections** are lists in the content files
  (`[[home.features]]`, `[[home.showcase]]`); icons are SVG files in
  `templates/icons/`, referenced by file name.

### Demo

Fill in the `[demo]` section in `config.toml`:

```toml
[demo]
url = "https://demo.byro.info"
username = "…"
password = "…"
```

With `url` set, the build adds `/de/demo/` and `/en/demo/`, links them in the
navigation, the home page and the footer, and lists them in the sitemap. With
`url` empty, none of this appears. The login data is published on the website,
so only use credentials of a dedicated demo account.

### Screenshots

The screenshots in `static/img/screenshots/` show byro v2026.4.0 with the data
from `make_testdata`, taken from a local installation with Docker Compose
(see the byro documentation). The user interface language comes from
`BYRO_LANGUAGE_CODE`, so the German and English screenshots are taken in two
runs. Each screenshot is a 1280×800 browser viewport at device pixel ratio 2,
saved as WebP in two widths:

```console
$ cwebp -q 80 -m 6 shot.png -o <name>-<lang>-2560.webp
$ cwebp -q 82 -m 6 -resize 1280 0 shot.png -o <name>-<lang>-1280.webp
```

When replacing them, keep the file names, update the version in
`screenshot_caption` and in `footer_credits`, and keep the alt texts in the
content files accurate.

### Preview images and icons

`static/img/og-de.png` and `og-en.png` (1200×630, Open Graph preview),
`favicon-32.png` and `apple-touch-icon.png` were rendered once from
`static/img/byro-logo.svg` and the Inter font. If the logo or the tagline
changes, render them again in the same size.

## Languages

- `/de/` and `/en/` never redirect; they always show their language.
- The language links in the header and footer point to the same page in the
  other language. Clicking one stores the choice in the browser
  (`localStorage`, key `byro-lang`).
- `/` is a short German page with links to both versions; it works without
  JavaScript and is the `x-default` target of the hreflang links. With
  JavaScript, it immediately forwards to the stored language, or else to the
  first browser language that the site offers, or else to
  `site.browser_fallback_language` (English).

## Deployment

`.github/workflows/pages.yml` runs on pull requests, on pushes to `main` and
manually (`workflow_dispatch`):

1. Install the pinned dependencies and run the tests.
2. Build and check the site for `https://byro.info` and for the project URL
   `https://<owner>.github.io/<repository>`, so that broken paths under either
   URL fail the run.
3. On `main` only: read the actual Pages URL with `actions/configure-pages`,
   build for that URL, upload it with `actions/upload-pages-artifact` and
   publish it with `actions/deploy-pages`.

Pull requests and manual runs on other branches only check and build; they
never publish. The workflow grants each job only the permissions it needs
(`contents: read` and `pages: read` for building, `pages: write` and
`id-token: write` for deploying). The actions are pinned to the commit of their
release; update the SHA and the version comment together.

Because the deployment reads the Pages URL, the site works both under a
temporary `https://byro.github.io/website/` and under `https://byro.info/`
after the custom domain is set up. A `CNAME` file is not needed and would be
ignored: with a GitHub Actions deployment, the custom domain is configured only
in the repository settings.

## Setting up GitHub Pages and byro.info

These steps need organization or repository admin rights and access to the DNS
zone of byro.info. They are not automated. The repository byro/byro.cloud and
its domain are not affected.

### 1. Make Pages available

The byro organization uses the GitHub Free plan. On that plan GitHub Pages only
works for **public** repositories, and byro/website is currently private. The
repository must be made public before the first deployment (or the
organization needs a paid plan).

### 2. Enable Pages with GitHub Actions

Repository *Settings → Pages → Build and deployment → Source:* select
**GitHub Actions**. The first push to `main` (or a manual run of the "Website"
workflow on `main`) then publishes the site at
`https://byro.github.io/website/`. The `github-pages` environment that GitHub
creates only allows deployments from `main` by default; keep it that way.

### 3. Verify the domain for the organization

Recommended by GitHub before adding the domain to a repository, to protect it
against takeover. Organization *Settings → Pages → Add a domain*, enter
`byro.info`. GitHub then shows a TXT record named
`_github-pages-challenge-byro.byro.info` with a value to create at the DNS
provider (INWX). After the record is visible, return to the same page and
choose *Continue verifying → Verify*. Verification also covers immediate
subdomains such as `www.byro.info`.

### 4. DNS records for byro.info

According to the GitHub documentation
([Managing a custom domain](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site),
checked November 2026):

| Name | Type | Value |
|---|---|---|
| `byro.info` | A | `185.199.108.153` |
| `byro.info` | A | `185.199.109.153` |
| `byro.info` | A | `185.199.110.153` |
| `byro.info` | A | `185.199.111.153` |
| `byro.info` | AAAA | `2606:50c0:8000::153` |
| `byro.info` | AAAA | `2606:50c0:8001::153` |
| `byro.info` | AAAA | `2606:50c0:8002::153` |
| `byro.info` | AAAA | `2606:50c0:8003::153` |
| `www.byro.info` | CNAME | `byro.github.io` |

As of November 2026, `byro.info`, `www.byro.info` and `demo.byro.info` all
have an A record pointing to `185.181.104.242`. Replace only the records for
`byro.info` and `www.byro.info`; leave `demo.byro.info` as it is. Do not add
wildcard records.

### 5. Set the custom domain

Repository *Settings → Pages → Custom domain:* enter `byro.info` and save.
GitHub checks the DNS records and then provisions a certificate; once that is
done, enable **Enforce HTTPS**. With both `byro.info` and `www.byro.info`
configured, GitHub redirects `www` to the apex domain. Afterwards, run the
workflow on `main` again (or push a change) so that canonical URLs, hreflang
links and the sitemap use `https://byro.info`.

## Open items

- **Imprint and privacy policy:** the site has neither. Whether a German
  website of the byro project needs an imprint (§ 5 DDG) and a privacy policy
  has to be decided by its operator. Missing for both: who operates the site
  (name or association, postal address, contact e-mail), and for the privacy
  policy also a description of the hosting by GitHub Pages, which processes
  visitors' IP addresses. The site itself uses no cookies, tracking or
  third-party resources; it only stores an explicitly chosen language in the
  browser.
- **License of this repository:** no license has been chosen for the website
